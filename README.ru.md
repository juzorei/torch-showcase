# Torch — публичная документация проекта

[English](README.md) | [Русский](README.ru.md)

**Состояние проекта на 2026-10-18:** основные компоненты кампании и конечного автомата (FSM), управления, навигации и отслеживания реализованы. Интеграция и офлайн-проверка продолжаются. Полное автономное прохождение кампании и приёмочные испытания удалённой группы исполнителей ещё предстоят.

**Статус публичных материалов:** отобранная текстовая документация опубликована с разрешения владельца. Запускаемых компонентов здесь нет. Процент готовности и срок выпуска не заявлены.

Исходный проект остаётся закрытым. Этот отдельный набор документов описывает возможную будущую демонстрацию, которую можно будет запустить. Здесь нет исходного кода, исполняемого демо, инструкций по развёртыванию или готовой к запуску версии. Исполняемая версия и демо не опубликованы. Для будущих дополнений нужны отдельное явное разрешение и проверка содержимого.

## Главная идея будущей демонстрации

**Автоматизация с проверяемыми результатами: отказоустойчивое управление, планирование навигации и офлайн-воспроизведение событий на синтетических примерах, доступных для анализа.**

Цель — показать, как система автоматизации оценивает прогресс, работает с неопределённостью, планирует движение и позволяет разбирать принятые решения. Будущая демонстрация должна одинаково ясно показывать и успешное поведение, и границы, за которыми возникают сбои. Это цель для будущей проверки, а не утверждение, что закрытая система уже ей соответствует.

## Архитектура в общих чертах

Основные слои закрытого проекта:

| Слой | Роль в будущей демонстрации |
| --- | --- |
| Кампания / конечный автомат (FSM) | Продвижение по кампании, переходы между состояниями и явные условия остановки. |
| Слой управления | Координация, границы выполнения команд и обработка сбоев. |
| Навигация | Планирование маршрутов и решения о движении. |
| Трекер | Наблюдения, отслеживание прогресса и данные для анализа. |
| Экспериментальная группа исполнителей | Исследование координации нескольких исполнителей и правил их ротации. |

Само наличие слоя не подтверждает надёжность системы в целом или готовность к внешнему использованию.

## Текущий этап

- Исходный проект — рабочая копия, в которой активно развиваются функции, а не зафиксированный релиз.
- В истории есть как успешные прогоны, так и прогоны со сбоями. Ни те ни другие не подтверждают, что текущая рабочая копия полностью проверена.
- Для этого среза состояния нет отслеживаемой проверки CI, на которую можно сослаться.
- Полная проверка текущего состояния для этого среза не подтверждена.
- Полное автономное прохождение кампании, восстановление из контрольных точек, подключение удалённых виртуальных машин и возможности группы исполнителей не доказаны. Приёмочные испытания удалённой группы ещё предстоят.

Реализация основных слоёв — важный инженерный этап, но не результат сквозных приёмочных испытаний. Этот срез состояния не подтверждает готовность релиза.

## Почему запускаемые демонстрации ещё не готовы

Остаются нерешённые вопросы: внутренний интерфейс RPC/shell нельзя считать доверенным; обрезка записей не удаляет из них чувствительные данные; в контрактах удалённого адаптера и трекера есть пробелы; правила ротации исполнителей не определены окончательно; нужна проверка чувствительных артефактов, лицензий и происхождения материалов. Эти ограничения нельзя скрывать за хорошо оформленным демо.

## Что планируется дальше

Предлагаются только синтетические офлайн-демонстрации: небольшой конечный автомат, примеры обработки сбоев, вымышленные графы навигации, воспроизведение искусственных событий и симуляция группы исполнителей в заданных пределах. Ни одна из них сейчас не включена в репозиторий и не заявлена как успешно проверенная. Результаты таких примеров подтвердят только их собственные свойства, а не характеристики работающей системы.
